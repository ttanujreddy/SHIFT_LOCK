# SHIFT//LOCK

SHIFT//LOCK is a 2D gravity puzzle game built with Unity. Navigate compact chambers by changing gravity, planning each shift carefully, activating switches, avoiding spikes, and reaching the exit. Gravity changes are limited by a per-level budget, so the route matters as much as the destination.

The project began from a Unity 2D puzzle-game template. The current original campaign contains three chambers with internal IDs 10–12 and player-facing labels Levels 1–3.

## Project setup

- **Unity Editor:** Unity 6, version **6000.5.9f1** (the course project version).
- **Project type:** 2D using the Built-In Render Pipeline.
- **Implementation:** C# scripts, Unity scenes/prefabs, and text-based level data.
- **Art/audio:** SHIFT//LOCK-specific pixel-art sprites and short sound effects are generated by C# at runtime; no separate sound pack is required.

Open the repository's Unity project root in Unity Hub with the required editor version. Let Unity finish importing assets and compiling scripts before entering Play mode.

## Run the game

Open `Assets/GravityPuzzleGame/Scenes/Menu.unity`. Select **Play**, then choose any of the three custom chambers. All three are directly selectable.

The scripts currently load scenes by build index, so preserve this order in **File → Build Profiles**:

- **Build index 0:** Menu.
- **Build index 1:** Game.

The Level Editor scene is for authoring layouts in the Unity Editor; it is not a runtime level-authoring feature.

## Controls

### Gameplay

| Input | Action |
|---|---|
| Left / Right Arrow | Move one cell relative to the current gravity orientation |
| W | Reverse gravity (opposite absolute direction) |
| A | Change gravity one step to the player's left |
| D | Change gravity one step to the player's right |
| S | No action; downward/player-relative gravity shift is intentionally unsupported |
| R | Reload the current chamber from its initial state |
| Escape | Return to the main menu |

Each successful gravity change consumes one shift. Requesting the current direction or trying to shift with an empty budget does not consume a shift. Gravity determines the direction the player falls; the camera rotates with it to help keep the puzzle readable.

### Level Editor

| Input | Action |
|---|---|
| Left Mouse Button | Place the selected tile in an empty cell |
| Right Mouse Button | Delete the tile under the pointer |
| R | Rotate the placement preview by 90 degrees |
| WASD / Arrow Keys | Pan the editor camera |
| Mouse Wheel | Zoom the editor camera |
| 5 | Select gravity switch |
| 6 | Select locked door |
| Escape | Return to the menu |

The editor is **Editor-only**. Saving writes a text file into the project's Assets directory and refreshes the AssetDatabase; it is not intended to run as an in-game editor in a built player.

## Gameplay rules

- **Gravity shifts:** GameManager checks the allowance before changing gravity. System resets use the low-level gravity method directly and do not consume a shift.
- **Gravity switch:** Contact activates the switch and opens every locked door in the chamber. The switch changes to its activated green visual, and the activation sound is played once.
- **Locked door:** A closed door is solid. When the switch activates, the door's scene object is destroyed and its logical grid cell becomes empty.
- **Spikes:** Falling onto a spike is fatal.
- **Exit:** Reaching the exit without being in a spike-death state completes the chamber.
- **Death/retry:** Death reloads the current Game scene. This resets player state, gravity, shift budget, switch activation, doors, and other scene state together.
- **Completion:** The game records the completed internal level in PlayerPrefs and displays a completion panel. The final custom chamber hides the Next Level button.

## Original chambers

Custom files retain their internal IDs so the original template data and per-level budget indexes do not have to be renumbered.

| Display name | Level file | Design focus |
|---|---|---|
| Level 1 — Power Cycle | `Level10.txt` | Gravity switch and locked door |
| Level 2 — The Dangerous Shortcut | `Level11.txt` | Route planning around a spike |
| Level 3 — Fail-Safe | `Level12.txt` | Two doors and multiple valid routes |

The three original chambers and menu progression have been tested in Unity. Level 12 has two validated routes, each requiring four gravity shifts. Only consecutive custom files beginning at internal ID 10 are displayed by the normal chamber-selection menu.

## Level text format

Level layouts are plain text assets in `Assets/GravityPuzzleGame/Resources/Levels/Level<id>.txt`. Each non-empty line describes one tile:

```text
x,y,tileId
```

Spike records require a fourth comma-separated field for rotation in quarter-turns:

```text
x,y,2,rotation
```

Coordinates are logical grid cells, not world units. The runtime maps a record at `(x, y)` to world position `((x + 1) * 9, (y + 1) * 9, 0)`. Valid file coordinates are 0–18 on each axis because the runtime uses a 20×20 grid with a one-cell coordinate offset.

| Tile ID | Tile | Behavior |
|---:|---|---|
| 0 | Block | Solid wall/platform |
| 1 | Player | Player spawn location |
| 2 | Spike | Hazard; fourth field specifies rotation |
| 3 | Exit flag | Completing contact wins the chamber |
| 4 | Gravity switch | Opens all locked doors on contact |
| 5 | Locked door | Solid until a gravity switch activates |

Blank lines are ignored. Malformed and out-of-range records are skipped with warnings. A level should contain a player spawn and an exit, plus any required switch/door objects. Avoid duplicate coordinates: a later record overwrites the grid cell reference, but an earlier instantiated visual may remain in the scene.

## Configuring shift budgets

GameManager has a serialized `gravityShiftsPerLevel` array. **Array element N configures internal level ID N.** The custom campaign therefore uses elements 10, 11, and 12 for `Level10.txt`, `Level11.txt`, and `Level12.txt`.

When changing a budget, update GameManager in the Game scene's Inspector and save `Game.unity`. Changing a C# field initializer does not overwrite a value already serialized in the scene. A code-defined fallback is used only when the selected internal ID has no entry in the array.

## Code map

| Script | Responsibility |
|---|---|
| `Scripts/GameManager.cs` | Loads level text, creates the runtime grid, enforces shift budgets, answers collision/floor queries, rotates gravity/camera, and opens doors |
| `Scripts/Player.cs` | Reads input, moves/falls, handles switch contact, spikes, death, and victory |
| `Scripts/GameUI.cs` | Shift counter, hints, compass animation, completion panel, next-level/menu actions |
| `Scripts/MenuUI.cs` | Menu pages, custom chamber buttons, visible/internal numbering, decorative menu styling |
| `Scripts/Pool.cs` | Loads base tile prefabs from Resources and maps IDs to prefabs |
| `Scripts/Tile.cs` | Plain serializable data for one grid cell; not a MonoBehaviour |
| `Scripts/LevelEditor/LevelEditor.cs` | Tile placement/deletion, grid validation, rotation, and text serialization |
| `Scripts/LevelEditor/LevelEditorCamera.cs` | Editor camera pan and zoom |
| `Scripts/CameraController.cs` | Gameplay camera follow/center toggle and zoom |
| `Scripts/ShiftLockTheme.cs` | Runtime-generated pixel art, palette, and UI styling |
| `Scripts/ShiftLockAudio.cs` | Generates/caches event-driven one-shot sounds and wires UI clicks |

### Generated art and audio

`ShiftLockTheme` draws tile textures from pixel rectangles, circles, and triangles. It uses point filtering and caches sprites by tile ID, dimensions, pixels-per-unit, and normalized pivot. The generated art changes rendering only; transforms and colliders still define gameplay geometry.

`ShiftLockAudio` synthesizes short mono effects in memory at 22.05 kHz and plays them through a persistent, non-spatial AudioSource. Effects cover movement, gravity shift, switch activation, death, victory, and UI clicks. There is intentionally no background music.

## PlayerPrefs

- `SelectedLevel`: the internal numeric level ID selected from the menu.
- `Level<id>`: template progression status, where 0 means locked, 1 unlocked, and 2 completed.

All three custom campaign buttons are directly selectable. Completion still writes per-level status and attempts to unlock the next internal ID, even though the normal menu exposes only the three original chambers.

## Known MVP limitations

- The project retains some original template structure and legacy level data.
- The original menu decorations had inconsistent scene transforms; slight visual overlap is accepted for this MVP.
- The Level Editor saves files only inside the Unity Editor.
- This is a small playable MVP demonstrating gravity shifts and original switch/door puzzles, not a fully expanded commercial game.
